# @affidavit/db

**Owner:** Lane 1 (Intake and Platform)

**Mission:** Drizzle schema and migrations, row-level security, the Graphile Worker stage queue, and the real `CaseStore` and `EventSink` (`PgCaseStore`, `PgEventSink`).

## Commands

Run from this directory, or add `--filter @affidavit/db` from the repo root.

- `pnpm typecheck`, `pnpm lint`, `pnpm test` (pure unit tests only)
- `pnpm test:pg` runs the Postgres suites. It needs `AFFIDAVIT_TEST_DATABASE_URL`, the superuser URL of a throwaway server (for example compose Postgres). Each suite creates and drops its own database. Without the variable the suites skip with an explicit message. CI does not run them until a Postgres service is added.
- `pnpm db:generate` after editing `src/schema.ts`. Security objects (roles, RLS, grants, triggers) live in the hand-written `drizzle/0001_security.sql`; add later ones with `pnpm db:generate --custom --name=<name>`.

## Invariants

- Every table has `tenant_id`; RLS is enabled and forced on all of them; every foreign key includes `tenant_id`.
- Role model. `bootstrapRoles` runs once as a superuser (PG16 only lets a superuser set NOSUPERUSER/NOBYPASSRLS, role-level settings or a database owner): it creates `affidavit_owner` (non-superuser database owner), `affidavit_app` and `affidavit_worker`, pins the login roles' `search_path`, and makes the owner the database owner. `applyMigrations` then runs as `affidavit_owner`; the migration only verifies the login roles' flags. The owner owns every object, including the SECURITY DEFINER functions, and is subject to FORCE RLS (explicit `owner_access` and `owner_read` policies on `tenants`, `stage_jobs`, `stage_runs`, `cases`, `stages`). Passwords are set at provisioning (`setRolePassword`, SCRAM verifier), never in a migration or a committed file. The two login roles are plain (no BYPASSRLS, no memberships, no TEMP, nothing owned): `affidavit_app` (tenant tables under RLS, plus `enqueue_stage()`) and `affidavit_worker` (queue schema and `claim_stage_run()`, no tenant tables). Open pools only with `openPool(url, role)`, which refuses a superuser, any membership, REPLICATION, role-level settings other than `search_path`, owned objects, the wrong role, or a wrong `search_path`.
- Tenants are created by the owner (`provisionTenant`), not the app role.
- Tenant is set per transaction (`withTenant`, `set_config(..., true)`), and the connection is `DISCARD ALL`ed before it returns to the pool. No tenant set means no rows. RLS defends against query-building bugs; code with arbitrary SQL as the app role could still call `set_config`.
- Known limits, for Adrian: the worker role can DELETE and UPDATE Graphile job rows (Graphile needs it), so failed-job records are not tamper-proof; the worker process also holds the app pool, so a compromised worker can act as any tenant through it; `exhibits.result` and verdict writes go through the app role. None of these is closed by this package. Port writes are not lease-fenced: `PgCaseStore` and `PgEventSink` write in their own transactions and do not check the lease, so a zombie handler that ignores `ctx.signal` can still write through them (a question for the lead; a fence would need the lease token on every port call). Also: Postgres denies the app role `ALTER ROLE ... SET app.tenant_id` (tested); a role-level `search_path` change would fail closed at the next `openPool`; and `provisionTenant` needs the owner credential in whatever process calls it (a follow-up could add a SECURITY DEFINER `provision_tenant` for a narrow role; not built).
- READ THIS BEFORE WRITING THE ORCHESTRATOR (L1-10). (1) Abandon attempt N (`failStageRun`, which needs an expired lease) BEFORE enqueueing N + 1: `claim_stage_run` refuses a second open attempt of the same visit, so N + 1 would fail at claim otherwise. (2) A handler must check `ctx.signal.aborted` before every write it makes through a port (`PgCaseStore`, `PgEventSink`); those writes are not fenced by the lease. (3) `listFailedStageJobs` and `stageJobState` treat a job with its attempt used up and no lock as failed even with no error (graphile-worker 0.18 clears the lock of jobs locked for over 4 hours without recording one).
- Handler ordering: make the last writes (including the case transition through `PgCaseStore`) first and call `ctx.complete(tx)` last. `resumeDecision` returns `completed-not-advanced` for a completed attempt whose case is still at that visit of a non-terminal stage, so a handler that completes without advancing is not mistaken for a finished stage. `pg_advisory_xact_lock` on tenant, case and stage serialises `enqueue_stage` and `claim_stage_run`. Adoption (`completeStageRun` without a token) is refused in SQL unless the case has left the visit.
- `openPool` returns a branded `CheckedPool`; the stores, the sink and the queue functions only accept `AppPool` or `WorkerPool`. Heartbeat failures abort `ctx.signal` once the last confirmed lease expiry has passed or after three failures in a row. `src/kill-child.ts` is a test helper (a worker in its own process, run through tsx, given only the app and worker URLs) used by `kill.pg.test.ts`; it is not part of the package API and is never emitted (the build is noEmit).
- The app role cannot touch the Graphile Worker tables. It enqueues only through `enqueue_stage()` (SECURITY DEFINER; tenant forced from the transaction setting; checks the case exists; writes a durable `stage_jobs` record; returns false when the key is already queued, running or failed). The worker role claims through `claim_stage_run()`, which refuses a payload with no matching `stage_jobs` record, so a forged or rewritten job fails at claim and shows in `listFailedStageJobs`. An attempt starts at most once (`stage_runs`, with a lease). Handlers get a `StageContext`: complete the attempt in the handler's own final transaction (`ctx.complete(tx)`). Handler errors set `failed_at` and `error`. Leases are enforced in SQL: the app role has no UPDATE on `stage_runs` and cannot read `lease_token`. `claim_stage_run` hands the claimer a secret token; heartbeat and holder completion (`stage_run_heartbeat`, `stage_run_complete`, which run in the caller's transaction) need that token and a live lease; the orchestrator can abandon (`failStageRun`) or adopt (`completeStageRun`) only an EXPIRED lease; a lease is capped at an hour (claim) and the database refuses to extend an expired one. The task wrapper heartbeats every lease/3 and aborts `ctx.signal` when it cannot. Writes through other ports (`PgCaseStore` opens its own transactions) are not atomic with `ctx.complete(tx)`; a kill between them leaves the attempt open and the orchestrator adopts it once the case has left the stage. `enqueue_stage` requires the case to be at that stage now, records the stage visit (stage-history ordinal, written by a trigger on `cases`; the app role cannot insert history), and refuses to reuse an attempt number for a later visit. `claim_stage_run` refuses a job whose case left the stage or visit, a superseded attempt, or a second open attempt of the visit; the refusal fails the Graphile job. A killed worker leaves an open attempt (or, if it died before claiming, a stale-locked Graphile job with no error). The orchestrator (L1-10) calls `resumeDecision({ appPool, workerPool }, p)`, which also reads the queue job state: `next-attempt` means abandon if open, charge budget, `enqueueStage` with attempt + 1 (attempt numbers must be unique per case and stage across visits); `adopt-complete` means the case left the visit and the lease is gone. Graphile retries are off (`max_attempts` 1): resume is explicit, and `listFailedStageJobs` surfaces failed and stale-locked jobs.
- Append-only (triggers stop the application roles; the owner could still disable them): verdicts, events, ballots, stages, cost_rows, escalations, stage_jobs. Write-once: `exhibits.result`, `stage_runs.completed_at` and `failed_at`. Inserts are guarded too (cases start at intake with zero counters, exhibits and stage runs start without a result). `cases` identity, file, score and floor are immutable; stage changes are also checked in SQL (table, F3, appeals). An event's seq must be below the case counter (call `nextSeq` first); ballots and escalations need their event row; `cost_rows` amounts are non-negative. Verdict insertion does not check the case stage (parity with `FakeCaseStore`; a question for Adrian).
- Migrations must run as the designated owner role: the `owner_access` policies on `tenants`, `stage_jobs` and `stage_runs` name the role that ran them. After a Graphile Worker upgrade, re-run `applyMigrations` to grant and add policies for new queue tables.
- Budget arithmetic: `remaining_usd` is exact `numeric` rounded half away from zero at 6 decimals; `FakeCaseStore` rounds a float with `Math.round`. They can differ by one micro-dollar on exact half-micro values.
- `AFFIDAVIT_TEST_DATABASE_URL` must never point at a shared server: the tests create and alter cluster-wide roles (`affidavit_app`, `affidavit_worker`) and temporary roles. Use a throwaway container.
- Every function pins `search_path`; raw SQL names `public.<table>` (Drizzle cannot qualify `public`).
- Store rules match `FakeCaseStore` in `packages/testing`: `rejectTransition` plus a row lock in `transition`. Add a case to `src/transition-cases.ts` for any rule change.
- Queue jobs are keyed on tenant, case, stage and attempt.
- Add a new tenant table: schema, migration with FORCE RLS, policy and grants, and a line in the isolation test.
