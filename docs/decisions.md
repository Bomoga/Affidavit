## Decisions made

- 2026-11-05: Contracts v1.0 resolves the Lane 3 contracts draft: four-level severity, prompt-id keyed `promptVersions` and `modelIds`, per-question ballots, `Witness.sha256`, optional `Verdict.severity`. See `packages/contracts/CHANGELOG.md`.
- 2026-11-05: Internal packages export TypeScript source (`exports` points at `src/index.ts`) and `tsc` runs with `noEmit`. Real builds arrive with the apps that need them.
- 2026-11-05: Dependency versions are pinned exactly, and the pnpm release-age gate stays on. Versions published inside the gate window were replaced by the newest older release instead of adding exclusions.
- 2026-11-05: Dependency install scripts stay disabled except esbuild. Native tree-sitter builds are not used; Lane 1 loads grammars through `web-tree-sitter` (wasm).
- 2026-11-05: `.claude/settings.json` does not allow `docker run` or `docker build` without a prompt. Substring deny patterns cannot make raw docker safe (a security review flagged `-v /:/host` style bypasses). Lane 2 should add a fixed wrapper script (argv from `buildDockerRunArgs`, images allowlisted by digest, mounts restricted to the workspace) and allow only that. This differs from P0-06 as written in the implementation plan.
- 2026-11-20 (lead, L2-04c, PR stacked on #46): NodeGoat gets its dependencies through a pinned dependency bundle, built outside the jail from the corpus lockfile and mounted read only into the boot build. An egress exception was declined, and so was a js-yaml-style shortcut. The bundle is built by a human on a networked host (`packages/sandbox/scripts/build-dependency-bundle.ts`, `npm cache add --ignore-scripts`, every lockfile hash checked), never by the Judge or an agent path. It is content addressed (sha256 of the tar, pinned in `docker/sandbox/dependency-bundles/pins.json`), and the build fails closed on a mismatch. It has separate, individually hashed production and dev sections, so the runtime image mounts production only and the suite build mounts both (review of #46: without dev dependencies no real patch could pass the suite). A package that needs a lifecycle script makes its section `unsupported`, by name. Details: `docs/lanes/lane2/boot-recipes.md`, "Dependency bundles".

- 2026-11-21 (#55 re-review, decided by the reviewer while the lead was away): dependency bundles allow a `prepare` script in a registry tarball package, since npm runs `prepare` only for the root project and git or folder sources and the install uses `--ignore-scripts`. - 2026-11-21 (Lane 2, PR #64, awaiting the lead's confirmation): `runAddedTests` picks the runner for the patch's added test files from the vulnerable commit's root `package.json`, by declared dependency or devDependency, in the order vitest, then jest, then mocha (`testRunnerOf` in `packages/judge/src/jail/workbench.ts`). A target that declares none of them, or uses another runner, gets no added-tests run (null, which changes nothing). Reverse or extend this if the lead disagrees.
- 2026-11-21 (Lane 1, L1-18, awaiting the lead's confirmation): real intake runs Semgrep and gitleaks on `GvisorToolRunner` with no change to `packages/sandbox`. Of the two options for the `/tmp` conflict, the Lane 1 one was chosen: discovery no longer mounts anything at or under `/tmp` for those tools and uses the jail's own `/scratch` (`TMPDIR` and `HOME`), a capped tmpfs that never touches the host disk. Semgrep runs behind a constant `/bin/sh` wrapper that keeps a `TMPDIR` the runner set and falls back to a per-run scratch mount at `/var/tmp` under plain Docker, because without a writable temp directory the pinned Semgrep exits 0 with an empty report. gitleaks needs no temp directory (checked on the pinned image). Discovery sets every mode with `chmod` (report file pre-created 0666 by the worker in a 0755 `/out`, scratch subdirectories 0777, read added for others on what the owner can read in `/src`), so the worker's umask no longer matters. The jail is unchanged: uid 65534, `--network none`, read-only root, no credentials, egress guard untouched. Open: OSV-Scanner still needs a temp directory and its database under `/tmp`, so it runs on plain Docker only until the tool runner can give it one (PR #45 is the draft); real intake does not run it, startup logs `intake: dependency scan not run`, and CR-14 asks for a scanner-coverage note in the case file. After review: the wrapper exits 97 (a failure) when its temp directory is missing or a probe byte cannot be written there; every Semgrep run carries a liveness canary (its own rule and file, outside the production rule pack, mounted at `/canary`) that must match exactly once, or the run throws `ToolOutputMissingError`, and whose results are stripped before the report is read; scanner runs get a 512 MiB `/scratch` and 2048 MiB of memory through the existing `limits` option (no sandbox change); `runTool` refuses output and scratch directories whose parent is not a 0700 directory of the worker; `shareForJailRead` uses `O_NOFOLLOW` and `fchmod` and refuses entries that are not files, directories or links.
