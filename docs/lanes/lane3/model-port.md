# Real model port (L3-15)

`AnthropicModelPort` in `packages/trial/src/model/` is the real `ModelPort`. It runs each agent turn on the Claude Agent SDK (`@anthropic-ai/claude-agent-sdk` 0.3.318, already pinned in the lockfile by P0-02; nothing new was installed). With it wired, the only thing a real trial still needs is an API key.

## Turning it on

1. The lead creates a dev key in the Anthropic Console organization for the product runtime (plan.md, Human prerequisites), **with a monthly spend limit set on that key in the Console before first use**. The per-case budget in the orchestrator is a second line of defense, not a replacement for the Console limit.
2. Put the key in the shared secrets store and export it in the worker's environment only:

   ```sh
   # >>> API KEY GOES HERE, from the secrets store. Never commit it, never paste it into a file in the repo. <<<
   export ANTHROPIC_API_KEY="<from the secrets store>"
   ```

3. Select the real trial implementation and the model mode:

   ```sh
   export AFFIDAVIT_TRIAL_IMPL=real
   export AFFIDAVIT_MODEL_MODE=live        # live | record | replay; default live
   ```

4. Optional settings:

   | Variable                                | Meaning                                                                                                                                                   | Default              |
   | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
   | `AFFIDAVIT_MODEL_TIMEOUT_MS`            | Wall-clock cap per agent turn (1000 to 3600000)                                                                                                           | 300000 (placeholder) |
   | `AFFIDAVIT_RECORD_DIR`                  | Where record mode writes. Required for `record`; record refuses to start without it                                                                       | none                 |
   | `AFFIDAVIT_MODEL_FIXTURES_DIR`          | Where replay reads                                                                                                                                        | `fixtures/models/`   |
   | `AFFIDAVIT_ENV`                         | Deployment environment. `record` and `replay` start only when it is `development` or `test` (trimmed, any case). Unset or anything else means `live` only | none                 |
   | `AFFIDAVIT_RECORD_ALLOW_SECRETS`        | `1` records a submission verbatim even when it holds credential-shaped text (see Record and replay)                                                       | unset                |
   | `AFFIDAVIT_MODEL_CONFIG`                | JSON file `{ "models": { "<prompt id>": "<model id>" } }`                                                                                                 | none                 |
   | `ANTHROPIC_MODEL_DEFENSE`               | Model for prompt `defense`                                                                                                                                | `claude-opus-5-5`    |
   | `ANTHROPIC_MODEL_DEFENSE_SECOND`        | Model for `defense-second-attempt`                                                                                                                        | `claude-sonnet-5-5`  |
   | `ANTHROPIC_MODEL_PROSECUTION`           | Model for `prosecution`                                                                                                                                   | `claude-opus-5-5`    |
   | `ANTHROPIC_MODEL_REMEDY`                | Model for `remedy`                                                                                                                                        | `claude-opus-5-5`    |
   | `ANTHROPIC_MODEL_JUROR_SECURITY`        | Model for `juror-security`                                                                                                                                | `claude-opus-5-5`    |
   | `ANTHROPIC_MODEL_JUROR_MAINTAINABILITY` | Model for `juror-maintainability`                                                                                                                         | `claude-sonnet-5-5`  |

   Precedence is defaults, then the config file, then the per-prompt variables. The table is checked at startup: an id not in `KNOWN_MODEL_IDS` fails closed, both Defense attempts on one model fails (F3), and two jurors on one model fails (F4). The defaults are starting choices, not tuned ones.

**Wiring status.** `apps/worker` (Lane 1) still throws `NotWiredError` for `AFFIDAVIT_TRIAL_IMPL=real`. Wiring is one call in the composition root, `createModelPortFromEnv(process.env, { killSwitch })`, passed as the orchestrator's `model`, and each handler's `model` taken from `modelFor(resolveModelTable(process.env), promptId)`. That change is in Lane 1's paths, so it is not in this PR.

## What the agent gets

One turn is one Agent SDK session that can only call its role's submit tool.

- `allowedTools` is exactly the role's allowlist from `ROLE_TOOLS`, as `mcp__affidavit__submit_*`. Each advertised input field is its contract schema (`WitnessSubmission`, `PatchSubmission`, the ballot options, and `ParamSpace` for counterexamples until CR-T8) or any JSON value, and optional, so a runtime that validates input before hooks can never bounce a malformed call back for a retry. The orchestrator checks the contract schema afterwards.
- The submit server and each submit tool set `alwaysLoad: true`, so the tools are never deferred behind tool search. With `tools: []` there is no search tool, so a deferred submit tool could never be found.
- `tools: []` removes every built-in tool; `disallowedTools` names them again (every tool input type in the SDK 0.3.318 `sdk-tools.d.ts`, plus `PowerShell`, `ToolSearch`, `SendMessage`, `TaskOutput` and the other runtime tools). `permissionMode: 'dontAsk'`, so anything not pre-approved is denied and nothing prompts.
- The only tool server is the in-process submit server; `strictMcpConfig` ignores every other MCP configuration. No skills, plugins, or subagents.
- `settingSources: []`, and the cwd is a fresh empty temp directory (removed afterwards) that is also the agent's home, config, and temp directory, so no settings, memory, or CLAUDE.md from a repo or a user can load.
- **The worker image must contain no managed-settings file** (for example `/etc/claude-code/managed-settings.json` on Linux, `/Library/Application Support/ClaudeCode/managed-settings.json` on macOS, `C:\Program Files\ClaudeCode\managed-settings.json` on Windows). `settingSources: []` does not stop the runtime reading managed (policy) settings, and such a file could add tools, hooks, MCP servers or permissions. The image build should check that the path is absent.
- The system prompt must equal the packaged prompt for that id and version, or the call is refused. Case content goes only in the user message, inside the untrusted wrapper.
- The first submit call is captured exactly as sent and ends the turn, on every path: the PreToolUse hook captures it and stops; if a runtime bounced it on validation before PreToolUse, the PostToolUseFailure hook captures the raw input and stops; if the handler ran, PostToolUse stops. A later call never replaces it. Malformed output reaches the orchestrator and is recorded as `exhibit-inadmissible` (rule `schema`), not retried.
- The submission is never rewritten. The Judge must run the witness the agent submitted, and the exhibit must match it byte for byte, so a witness containing `Authorization: Bearer ...` or `?token=...` passes through unchanged. Only the exact key value is checked: a submission containing it throws `ModelCallError` and is neither returned nor recorded.

## Key handling

The key is read from `ANTHROPIC_API_KEY` on every call and goes only into the agent process environment. Every error, log line, and recorded field other than the submission is scrubbed of the key by value, of anything shaped like an Anthropic key, and of the values of credential headers, assignments and URL parameters (`x-api-key`, `Authorization: Bearer`, `ANTHROPIC_API_KEY=`, `?key=`). Text is always redacted whole before it is shortened, so a key cut by a length limit cannot leave a fragment behind. A missing key throws `ModelUnconfiguredError` (code `model-unconfigured`) from the port's `preflight`, which the orchestrator calls before it charges the turn's budget, so the case halts with `{ status: 'halted', reason: 'model-unconfigured' }`, nothing charged, nothing escalated. A key the provider rejects also halts the case, but after the charge, since the call was made.

## Budgets and caps

The orchestrator still charges the whole turn budget before the call. A failed call whose spend the runtime reported (a result arrived, or the provider refused the request with a class decided before any work, `invalid_request`, `rate_limit`, `billing_error` or `authentication_failed`, and no token was used) carries that spend on `ModelCallError.cost`; the orchestrator records it in the ledger and gives back the unspent part through `OrchestratorDeps.settlement` when one is wired (CR-T1, Lane 1 has to wire it). A failure with unknown spend (any other class with no result, a timeout, an abort, a broken stream, or a reported cost that is not a valid `StageCost` with finite non-negative numbers) keeps the whole charge. A failed call that overspent its charge is charged the overage, and overdrawing the case makes it `budget-exhausted`, as on success. A failure while settling never replaces the call error; it is attached as `ModelCallError.settlementError`. The port also passes `maxTurns` and `maxBudgetUsd` to the SDK, aborts mid-turn when streamed token usage passes the token budget, enforces the wall-clock cap, and polls the kill switch (`abortAll()` aborts every turn in flight). Usage and cost come back from the SDK result. When a turn is cut off before a result arrives, the cost is reported as the whole turn budget, because the real figure is unknown.

Provider failures throw `ModelCallError`, never "no submission" or "turn cap", unless the agent had already submitted: a wall-clock timeout, an abort, a hung stream (the port stops waiting at the cap even if the stream ignores the abort), a transport error, a stream with no result, an execution error, or any assistant `error` code from the provider (`overloaded`, `rate_limit`, `server_error`, `billing_error`, `max_output_tokens` and the rest; `authentication_failed` is `model-unconfigured` instead), whatever the result's `is_error` says. Only an agent that used all its turns without submitting is `turn-cap`, and only a clean finish without a submission is `no-submission`. So an outage can never dismiss a candidate (F3).

## Diagnosing a provider error (L3-16)

A provider failure now reads like `agent turn failed: provider error invalid_request (HTTP 400): <shown fragments>`. The error class (from the runtime's closed set) and the HTTP status (the result's `api_error_status`) are always shown. The provider's text (the runtime's synthetic assistant message, or the result text) is never forwarded as is. It fails closed: a JSON error body is decoded, every field is redacted (the key by value and every pattern in `redact.ts`), and then only fragments rebuilt from a fixed allowlist of shapes are shown, joined with `; ` and capped at 300 characters. Each fragment is fixed text plus captures that are digits, a model id matching `claude-<name>-<n>[-<n>...]`, or a validation path made of a known request root, indices and a fixed vocabulary of request field names. Free text, including any echo of the request or the case file in any encoding (verbatim, JSON or unicode escaped, case-changed, whitespace-collapsed, partial), is never shown. Text matching no shape becomes `provider message withheld (does not match a known-safe shape)`. The request body is never included. The same line goes to the port log at `warn`, and the worker logs the error message. Runtime text on an error result (`error_during_execution`, `is_error`) goes through the same allowlist.

The key must be printable ASCII with no spaces. A key with a trailing newline or CR, a space, pasted quotes, or any other character fails `preflight` with `model-unconfigured` before any charge, because the runtime would refuse it as a header value.

The shapes that can be shown, and what each means for the first real run's `invalid_request`:

| Shown fragment                                                                                                                                                 | Cause                                                                                                                                                                                                                                 | First fix                                                                    |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `Invalid API key`, `Invalid X-Api-Key header value`                                                                                                            | The key reached the runtime in a shape it refuses (now caught by `preflight`). **Unverified:** that the runtime reports this client-side header error as `invalid_request` is read from the runtime's strings, not seen on a live run | Export the bare key                                                          |
| `organization has been disabled`, `credit balance is too low`                                                                                                  | The Console organization or key is disabled, or has no credit                                                                                                                                                                         | Fix it in the Console                                                        |
| `tools.<path>: <reason>` (for example `tools.0.custom.input_schema: JSON schema is invalid`)                                                                   | The API refused a submit tool schema (draft-07 `$schema`, `definitions`, recursive `$ref`, `propertyNames`, `anyOf`)                                                                                                                  | Simplify the advertised schema in `submit-tools.ts` (`submitInputShape`)     |
| `<param>: not supported` (`temperature`, `top_p`, `top_k`, `budget_tokens`, `thinking.type`, `effort`), `tool_choice: type "tool" and "any" are not supported` | A parameter the model refuses. The port sets none of these; the runtime chooses them                                                                                                                                                  | Set `thinking`/`effort` explicitly in the port options, or try another model |
| `prompt is too long: N tokens > M maximum`, `messages.<path>: <reason>`, `max_tokens: N > M, ...`                                                              | The user message (case file) is too long or not valid text, or the output cap is too high                                                                                                                                             | Check the case file slices and the turn token caps                           |
| `model: <id>`                                                                                                                                                  | Unlikely: an unknown model is a 404 and the runtime reports it as `model_not_found`                                                                                                                                                   | Check `ANTHROPIC_MODEL_*` and `AFFIDAVIT_MODEL_CONFIG`                       |
| `rate limit`, `overloaded`                                                                                                                                     | Capacity, not the request                                                                                                                                                                                                             | Retry later                                                                  |
| the JSON error type alone (`invalid_request_error`), plus `withheld`                                                                                           | The provider's text matched no known shape                                                                                                                                                                                            | Add a shape to `TEMPLATES` in `anthropic.ts` once the text is known safe     |

A `<path>` reason outside the fixed list (`JSON schema is invalid`, `Field required`, `Extra inputs are not permitted` and a few more) is shown as `(reason withheld)`.

## Probing a provider error (L3-17)

When the port's message is withheld, run the diagnostic probe. It makes a short ladder of tiny live calls with fixed synthetic text only (no case file, no repository content) and prints, for each probe, PASS or FAIL, the error class, the HTTP status, the request id, the runtime's version, model, key source and betas, the runtime's stderr tail, and the provider's raw error message after key and credential redaction. Raw provider text is safe to show here only because the input is synthetic; the probe refuses any probe whose input it did not build itself.

Export the key in the shell first. Never put it in the command, a file in the repo, or shell history:

```sh
# >>> API KEY GOES HERE, from the secrets store, typed into this shell only. <<<
export ANTHROPIC_API_KEY="<from the secrets store>"
# PowerShell: $env:ANTHROPIC_API_KEY = "<from the secrets store>"
node --import tsx packages/trial/scripts/probe-model.ts
```

The same model overrides as the worker apply (`ANTHROPIC_MODEL_*`, `AFFIDAVIT_MODEL_CONFIG`), so export them too if the worker has them. Flags: `--max-usd <n>` (total cap, default 0.50, at most 2), `--filler-kb <n>` (P5 size, default 16, 1 to 64), `--no-fetch` (skip P6). `pnpm --filter @affidavit/trial probe:model` runs the same script.

| Probe | What it sends                                                                                                                                                     |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1    | Bare SDK request on `claude-haiku-5-5`, "Reply with the single word ok", no tools                                                                                 |
| P2    | The same bare request once per distinct model id in the resolved model table                                                                                      |
| P3    | The port's own option set (`buildAgentOptions`) on the Defense model, trivial prompt, no submit tools                                                             |
| P4a   | P3 plus the Defense `submit_witness` tool, trivial system prompt                                                                                                  |
| P4b   | The real `AnthropicModelPort.runTurn` with the packaged Defense prompt and a synthetic user message                                                               |
| P5    | P4b with about 16 KiB of lorem filler, to rule out size                                                                                                           |
| P6a-c | Direct HTTPS to `https://api.anthropic.com/v1/messages`, bypassing the SDK: no tools, the advertised tool schema, and that schema without its top-level `$schema` |

Every probe runs (no early stop). Each SDK probe gets `maxBudgetUsd` 0.05, fetch probes `max_tokens` 16, and a probe is skipped once the total charged (reported spend, or the full 0.05 reserve when spend is unknown) would pass the cap. These are caps, not estimates; real cost per probe is [metric] until it has run. The run ends with a summary table and one interpretation line per pattern: P1 fails means a key or organization problem; P2 lists which model ids work; P3 failing with P1 passing means the SDK option set; P4a failing with P3 passing means the tool schema; P4b failing with P4a passing means the Defense system prompt; P5 alone failing means size; P6b failing with P6c passing means the `$schema` keyword. Exit code 0 when every probe passes, 1 when any fails, 2 for a missing or malformed key.

### Replaying the worker's Defense turn (P7, L3-18)

The default ladder is synthetic only. `--fixture-case <path>` adds P7, which replays the worker's own Defense turn on a checked-in fixture case file. The path must resolve (links followed) to a `.json` file directly inside the repo's `fixtures/casefiles/` (public corpus content, never a user repository), checked in and unmodified from HEAD (the file is read once, and the blob id of those bytes from `git hash-object --stdin --path` must equal `git rev-parse HEAD:<path>`, which also catches assume-unchanged and skip-worktree edits; git runs from the repo root with every `GIT_*` variable dropped and fsmonitor and hooks off; without git it is refused), at most 256 KiB, that parses as a contract `CaseFile`; anything else is refused before the banner and before any call. The user message is built by the real `defenseBlocks` (exported from `defense.ts`, the same function `createDefenseHandler` uses) and `renderPrompt`, as for a first attempt with no Judge feedback. A banner says that raw provider text is shown for this local diagnostic only; every printed line passes key and credential redaction. Fixture text is marked apart from synthetic text, and `runLadder` refuses it unless the script passed `allowFixtureInput`.

```sh
# >>> API KEY GOES HERE, from the secrets store, typed into this shell only. <<<
export ANTHROPIC_API_KEY="<from the secrets store>"
node --import tsx packages/trial/scripts/probe-model.ts --fixture-case fixtures/casefiles/nodegoat-nosqli-where-001.json --only-fixture --max-usd 2
```

| Probe            | What it sends                                                                                 |
| ---------------- | --------------------------------------------------------------------------------------------- |
| P7a              | The real Defense input from the fixture, the worker turn values, `runTurn` in live mode       |
| P7c:no-slices    | P7a with the code slices removed (candidate block only)                                       |
| P7c:trivial      | The synthetic P4b envelope with the worker turn values (isolates the budget mapping)          |
| P7b              | P7a in record mode, writing to a fresh temp directory that is removed afterwards              |
| P7c:slices-only  | P7a with only the code slices (no candidate block)                                            |
| P7c:probe-budget | P7a with the synthetic probe turn values (maxTurns 2, 200000 / 2000 tokens, the 0.05 reserve) |

The worker turn values come from the same variables apps/worker reads (`AFFIDAVIT_AGENT_MAX_TURNS`, `AFFIDAVIT_TURN_MAX_INPUT_TOKENS`, `AFFIDAVIT_TURN_MAX_OUTPUT_TOKENS`, `AFFIDAVIT_TURN_MAX_USD`), defaulting to 6, 100000, 8000 and 0.5, with the USD capped at 0.5 for the probe. Each P7 probe passes that USD as `maxBudgetUsd` and reserves it against the total cap; a refusal that reports no spend is charged the whole reserve. `--only-fixture` skips P1 to P6. For every P7 probe the report prints the status, class, refusal category and explanation (redacted), the raw provider message (redacted), the port's own message, the user message shape (bytes, lines, longest line, hash prefix, block labels; never its content), the turn values and how each reaches the SDK, and the SDK option values (names and numbers only; env variable names, never values).

### A refusal looks like `invalid_request`

The runtime (SDK 0.3.318) reports a response that ended with `stop_reason: "refusal"` (the model's safeguards declined the request) as an assistant error with the code `invalid_request`, the same code as a malformed request, and puts "safeguards flagged this message" text in its content. The port now tells them apart: such a message (or a `model_refusal_no_fallback` notice) is reported as class `refusal`. Its category is mapped onto an allowlist (`cyber`, `bio`, `chem`, `csam`, `frontier_llm`, `reasoning_extraction`); any other value becomes `other`, so no free string from the provider is passed on, and the explanation is never forwarded. A refusal is billed (the input was read), so it is never in `REFUSED_BEFORE_WORK`, and a result that reports zero spend for it counts as unknown spend: the up-front charge stands. Every assistant message (with or without an error code), the result's `stop_reason`, and the refusal notices are checked; any refusal sets a sticky flag that outranks every other outcome. A refused turn never returns a submission, even one captured before the refusal (the runtime can tombstone frames from a refused leg, and it carries on after errors such as `max_output_tokens`), and a refusal needs a reported USD above zero to count as known spend. A `model_refusal_fallback` notice (the runtime retried on another model) fails the turn whatever was submitted, since the verdict must record the model the table names; as a backstop for runtimes that send no notice, any assistant message whose `model` is not the requested id (an 8-digit date suffix and the runtime's own `<synthetic>` messages aside) fails the turn with class `model_mismatch`.

**Open decision (CR-T13 in `contract-requests-trial.md`).** The orchestrator treats a `ModelCallError` of class `refusal` as a plain call error: nothing in `packages/trial` retries or escalates it; the queue retries the stage, charging each retry, and then flags it for review. The lead decides whether a refusal should instead go to the second Defense attempt (a different model) or straight to human review. Whatever the choice, a refusal must never dismiss a candidate, least of all a high-arraignment-score one.

## Record and replay

- `live`: real calls, nothing written. The only mode allowed unless `AFFIDAVIT_ENV` is `development` or `test`.
- `record`: real calls, and each result is written to `$AFFIDAVIT_RECORD_DIR/<prompt id>/<input sha256>.json`. Record refuses to start without an explicit `AFFIDAVIT_RECORD_DIR` (there is no default) or outside development and test. A witness can quote credentials from the target repo (a hardcoded JWT, a cloud key). The submission is never rewritten, so a submission holding credential-shaped text is not recorded. One pattern set in `redact.ts` serves logs, errors and this check: Anthropic and OpenAI keys, AWS access key ids and secret keys next to `aws`, GitHub tokens, Slack tokens (`xox*-`, `xapp-`) and webhook URLs, Stripe secret, restricted and live publishable keys, Google API keys and `GOCSPX-` secrets, npm tokens, JWTs, PEM private key blocks, `scheme://user:pass@` URLs (empty user too, as in `redis://:pass@host`), `curl -u user:pass`, Azure `AccountKey=` and `SharedAccessKey=`, bearer and auth headers, credential query parameters, and `password`, `secret`, `token`, `api_key`, `authorization` or a `<word>_key`/`_secret`/`_token`/`_password` name (word: private, signing, encryption, secret, master, session, jwt, auth, access, refresh, client or webhook), with any name prefix and up to 32 suffix characters (`FOO_SECRET_KEY`, `SECRET_KEY_BASE`, `secretKey`, `private_key_id`), assigned a literal (quoted, 8+ characters; or unquoted, 6+ characters with a digit or symbol). An all-digit value is exempt only under a count-like name (`*_tokens`, `*_count`, `*_limit`, `*_size`, `*_length`, `*_ms`, `*_seconds`, `port`, `timeout`, `retries`, `ttl`), so `max_tokens: 100000` is clean, while 6+ digits assigned to `password`, `passwd`, `pwd`, `secret`, `api_key`, `token`, `key`, `pin`, `otp` or `auth` (`password=12345678`, `PIN: "123456"`) are flagged. Values that are code or placeholders are not flagged: `password = req.body.password`, `$TOKEN`, `'Bearer ' + token`, `{{token}}`, a quoted value that is one interpolation (`"${PASSWORD}"`) or one `$VAR`, a template literal starting with `${`, a quoted value with no run of 8 literal characters outside interpolations (`` `Bearer ${token}` ``), and member chains rooted at a known accessor (`process.env`, `settings`, `config`, `req`, `headers` and similar) that end where code ends, so `process.env.SECRET_KEY`, `settings.SECRET_KEY`, `os.environ['SECRET_KEY']` and `getenv('SECRET_KEY')` are clean. Letters-only and dotted opaque tokens in header and bearer positions are still credentials, as are `"hunter2hunter2${x}"` and a literal behind a placeholder (`process.env.X || '...'`, `.concat('...')`). The scan is linear-time, since repo content can shape the text: every pattern starts at a literal prefix with bounded repetitions and no backtracking through a body. No bound fails open: bearer, key header and query values are consumed to the end of their run, a quoted value longer than 256 characters is still a credential, a PEM block (blank lines, `Proc-Type`/`DEK-Info` headers and CRLF included) is redacted through its END line, or to the end of the text when there is none, and JWTs (also right after a hyphen, as in `x-eyJ...`) and `user:pass@` URLs of any length are matched as atomic runs that never overlap. A `$` inside a quoted value counts; only a leading `$` marks a placeholder. Strings over 256 KB are scanned in 64 KB windows overlapping by 8 KB for the bounded patterns, while the unbounded JWT and `user:pass@` patterns run once over the whole string so a long token is never split; strings over 8 MB are not scanned and are refused, and a scan past its 2 s work budget refuses the recording with a generic message (a log line or error over 256 KB, or past the budget, becomes `[redacted: oversized]`). A submission with credential-shaped text: the turn throws `ModelCallError`, with a message that names no value. Set `AFFIDAVIT_RECORD_ALLOW_SECRETS=1` to record it verbatim, and only for recordings you will not commit, or after review. If you scrub such a recording by hand before committing, add `"redacted": true` at the top level: replay then throws `JudgeIneligibleRecordingError` (a `ModelCallError`) instead of handing an altered witness to the Judge. A recording holds only the prompt id, version, model, input hashes, and the result (outcome, submission exactly as sent, redacted cost). Never the key, never request headers, never the request text. To add recordings to the repo, set `AFFIDAVIT_RECORD_DIR=fixtures/models` deliberately.
- `replay`: no key, no network, only in development or test. Reads `AFFIDAVIT_MODEL_FIXTURES_DIR` (default `fixtures/models/`). A request is served only if a recording matches its prompt id and its input hash (prompt version, model, system text, user content, tools, schema, turn cap, budget). Anything else throws `NoModelRecordingError`.

Recorded files are not yet mapped in the `packages/testing` fixture check, so recording into `fixtures/models/` makes that suite fail until CR-T11 lands.
