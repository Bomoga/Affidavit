## L1-17: the discovery re-scan (RescanPort)

- `DiscoveryRescan` copies the patched tree (no symlinks, no `.git`) into a fresh directory under the intake work root, quarantines it like intake, runs our Semgrep rules through the same `ToolRunnerPort` and normalizer, and removes the directory. The Judge's tree is never written.
- `clean` only when the candidate is a Semgrep finding, its file is a plain relative path that still exists in the patched tree as a regular file, the checks below hold, Semgrep reported no coverage loss, and no finding of the same rule id is in that file (as any merged member or as a skipped finding). The file and rule are compared, not the line range, because a patch moves lines; a second finding of the same rule elsewhere in the same file is not clean either (conservative). Everything else fails closed; a tool failure throws.
- Tests: `rescan.test.ts` (offline, Semgrep replaced behind the port by fixture SARIF), `rescan.docker.test.ts` (the pinned image, `AFFIDAVIT_DOCKER_TESTS=1`, also the recorder). The patched and shifted SARIF in `fixtures/corpus/rescan/derived/` is derived by hand from the real recording of the normalizer repo, not a tool run: the Docker test has not been run yet (the agent that wrote it was not permitted to run Docker). Rerun it with `AFFIDAVIT_RECORD_DIR` and replace them.
- Review of #66 (changes needed, fixed on the same branch): clean is never the default. It now also needs the case rule id among the rules the SARIF says Semgrep loaded (`rule-not-loaded`), the case file to be plain text Semgrep reads whole (no NUL, valid UTF-8, at most 1,000,000 bytes, no line over 4096 bytes; `not-plain-text`), and the exact file name in its parent's listing (a case-only rename is `file-missing`). The copy is capped by file count and bytes (`tree-too-large`, nothing scanned). A failed cleanup is logged and never changes the outcome. The coverage-loss refusal stays global (Semgrep notifications carry no reliable path), documented in `real-wiring.md` with [metric]. The Docker test gained hostile variants (`nosemgrep`, `.semgrepignore`, NUL, UTF-16, over 1 MB); still gated and not run yet.
- Wiring: `prepareCores` builds it from the intake settings and hands it to `createRealJudge` (`RealJudgeConfig.rescan`). With intake `fake` there is no re-scan and `verifyPatch` still fails closed (startup note).
- Known gaps: a patch that moves the vulnerable code to another file passes the re-scan (the witness family rerun still has to fail on the patched build); a patch that deletes or renames the case's file is never clean, so it goes to review. Results from real runs: [metric].
