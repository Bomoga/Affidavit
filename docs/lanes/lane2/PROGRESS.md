## Decisions made in this lane

- 2026-11-21 (CR-11): the Judge boots each case's targets itself (`CaseTargets`) and records the image digests as a Judge-owned value (`boot(...).digests`, for `BundleManifest.targetDigests`), not in the immutable case file. The Judge runs on a copy of the case file with the booted `imageDigest`s, so `BootedTargets` keeps its exact-image check. A boot failure throws `CaseBootError` before any witness runs. Proposed to the lead in `real-judge-host.md`; no contracts change.
- 2026-11-21 (CR-11 review 2): the startup orphan sweep is off by default and lease-based (`src/jail/lease.ts`): each worker records its case networks in a lease file with its host and pid, and a sweep removes only runs of an owner proven dead: same host, pid namespace and boot id, a heartbeat stale past 10 x its interval, and a pid that is gone or recycled (other start time). An unreadable lease stops the sweep; unclaimed runs need `AFFIDAVIT_SWEEP_ORPHANS=force`. A live worker's runs, another host's and unclaimed runs are never removed, because removing a live safe target would make a witness read as differential proof. The tree fingerprint now uses the staging walker, and path containment is decided on whole segments.

- 2026-11-14: A probe passes only if contained and recorded. Containment is judged from the host side where possible, and a probe with no start marker is never counted as contained.
- 2026-11-14: The containment runner feeds the probe on stdin and gives it a tmpfs `/scratch`, so no host path is mounted. It reuses `buildDockerRunArgs` so it measures the Phase 1 flags Lane 1 actually runs with.
- 2026-11-14: Follow-ups for the lead from the first run: add `--memory-swap` to `buildDockerRunArgs` (memory bound breached through swap), and decide on SELinux relabeling for tool mounts. Details in `containment.md`.
- 2026-11-14: The gVisor runner runs every container with `--security-opt label=disable`, because gVisor cannot start under an SELinux process label. Isolation comes from gVisor instead. Needs the lead's sign-off; see `sandbox-runner.md`.
- 2026-11-14: The witness writes its result through a single-file mount with `RLIMIT_FSIZE`, not a writable directory; the Judge reads it only after teardown, without following symlinks. Case networks are internal and give the host bridge no address. A tampered syscall trace fails `no-egress`.
- 2026-11-14: The witness runner image is built locally from a lockfile and run by image ID, which the sandbox now accepts as pinned alongside registry digests. Vitest is the version the repo already uses (5.1.0), as planned in `packages/judge/CLAUDE.md`.
- 2026-11-14: `@affidavit/judge` depends on `@affidavit/sandbox` (both Lane 2): the Judge owns the witness runner and is the only bridge to the sandbox.
- 2026-11-14: Lane 1 tools run on gVisor with the same flags but without the syscall trace. A witness run whose trace is malformed is refused, never judged.
- 2026-11-15 (PR #17 re-review): every patch file section must be headed `diff --git a/P b/P` with exactly `a/P` and `b/P` (or `/dev/null`) names, since `git apply -p1` strips the first component of any name; anything else is `schema`. The real workbench also compares `git apply --numstat` with the Judge's reading. **Interop for Lane 3:** Remedy must emit `git diff` style headers; a headerless unified diff is now `schema`.
- 2026-11-15 (PR #17 re-review): one patched build. The witness, counterexamples and the vulnerable commit's own suite all run on `PatchPlan.code`; the patch's own tests are an extra check whose failure counts and whose pass is never required. A patch may not add, delete or change any runner config, change `scripts` or a runner block in a `package.json`, or touch a test-like file outside a test root. Diff lines over 2000 characters are `schema`.
- 2026-11-15: `literal-only-patch` rejects any added code line that special-cases a witness value, not only patches whose sole change is that. Padding a patch with an unrelated hunk would otherwise get around it. Test files (only under a test root at repo or package root) are exempt, are left out of the target the witness runs against, and may not be referenced from code. See `patch-verification.md`.
- 2026-11-15: verifyPatch reruns the witness on the vulnerable commit too, so a witness that fails everywhere cannot make any patch look like a fix. An admissible counterexample that does not run cleanly on the patch counts as surviving.
- 2026-11-15 (lead decision, flagged on PR #17): a counterexample counts against a patch only after it is admitted on `vulnerable` and `safe` under every rule of evidence. Inadmissible and malformed counterexamples are reported `survived: false` and not used.
- 2026-11-15: verifyPatch mints the patch id (`{caseId, diff, kind: "patch"}`, the recipe Lane 3 already uses) and counterexample ids; submitted ids are never echoed. A patch whose `sha256` or `code` disagrees with its diff is `schema`. A patch that deletes or edits existing tests or test scripts is `suite-fails` before any build.
- 2026-11-15: A dirty re-scan shows only as `rescanClean: false`, because contracts v1.0 has no rule for it. A patch that does not apply is `schema`; one that does not build is `suite-fails`.
- 2026-11-20 (lead decision, CR-T8 resolved in Lane 2): verifyPatch reads the `// affidavit counterexample params:` header Lane 3 writes, runs each counterexample over those params, and mints its id from them (the id Prosecution computed). One result per submitted counterexample. A counterexample with a missing or bad header refuses the patch with `schema`, before any build. See `patch-verification.md`.
- 2026-11-17: `install-gvisor.sh` pins the SHA-512 of `gvisor.tar.zstd` for release 20261109.0 (x86_64 and aarch64), checked against the google/gvisor GitHub release's `SHA512SUMS` and GitHub's own asset digests, outside the bucket. Replaces the `[sha512]` placeholder from PR #14 review. See `sandbox-runner.md`.

- 2026-11-17 (L2-08): a bundle is a deterministic tar of canonical JSON; its address is the SHA-256 of the tar. `verdict.json` is the verdict without `bundleSha256`, which cannot be inside the bundle it names. The case file is listed in manifest `exhibits` under the id `casefile`, and each recorded result lives inside its exhibit record, because contracts v1.0 has no digest fields for them (v1.1 question for the lead). Submissions are stored as submitted, so replay reaches the same rejections.
- 2026-11-17 (L2-08): replay compares admissibility outcomes (`admissible`, `rejectedBy`, `passed`, `vulnPass`, `safeVariantFail`, `familyResults`, each run's variant, attempt and pass; every `VerifyResult` field), never timings or output digests. Without a sandbox Judge, `affidavit replay` checks integrity only and never reports success.
- 2026-11-17 (L2-08): `@affidavit/evidence` now lists `zod` 4.6.7 (the version `contracts` already pins, no new package in the lockfile) and has `@affidavit/judge` and `@affidavit/sandbox` as workspace devDependencies for the sandbox-host replay test; flagged for the lead.

- 2026-11-15: Targets are built with a split build, not `docker build` on their Dockerfile: only `npm ci --ignore-scripts` has network access, and everything that runs repository or package code runs offline in gVisor. See `boot-recipes.md`.
- 2026-11-15 (PR #18 review): the fetch allowlist is enforced by the network. Each build gets a fresh internal case network whose only peer is a CONNECT proxy (our code, under gVisor) that forwards only to `registry.npmjs.org:443` at host-resolved public IPv4 addresses. The earlier "only the registry resolves" design reached any IP literal and is withdrawn.
- 2026-11-15 (PR #18 review): npm for the fetch step runs from a Lane 2 image pinned by digest (`FETCH_IMAGE`), never from the target's base. Bases are restricted to official `node` images and refused if they carry `ONBUILD` triggers.
- 2026-11-15 (PR #18 review): compose files are parsed to a tree with `js-yaml` (core schema) and host-reading keys are refused at any depth, then Compose's normalized output is checked again. This adds `js-yaml` 4.3.2 as a dependency of `@affidavit/sandbox` (it was already in the lockfile transitively); flagged for the lead's approval.
- 2026-11-15 (PR #18 re-review): Compose's `config` runs on the host from a fixed absolute path, with a fresh empty 0700 directory outside the tree as its working directory, `HOME` and `DOCKER_CONFIG`; staging drops `.docker`. Before this, a repository could ship a Docker CLI plugin that ran unjailed on the host.
- 2026-11-15 (PR #18 round 3): build steps run with a 256 MiB per-file limit, and the tree is walked after the fetch and scripts steps against entry and byte caps before it becomes a build context. The janitor makes the tree writable before deleting, its exit is checked, and cleanup never throws (`leftovers` on the outcome instead). Build reasons use stderr only and are scrubbed of host paths. A quota'd work root is a host-setup requirement. Follow-up: sidecar image count and size caps, and image garbage collection.
- 2026-11-20 (lead decision on PR #46): a patch whose target suite is `unavailable` is rejected with `suite-fails` (fail closed). This supersedes the 2026-11-18 (L2-07) entry below, which reported an unavailable suite without holding it against the patch. `BootedTargets` serves a target only when the case file's `imageDigest` matches the booted image. A failed `prepare` always removes the patched case network (`ownBootedTarget`).
