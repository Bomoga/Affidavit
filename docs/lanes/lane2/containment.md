# Containment suite (L2-01)

The suite lives in `packages/sandbox/src/containment/`. Each probe is a small program that misbehaves in exactly one way and checks one invariant from the plan.md threat model. A probe passes only when both hold:

- **Contained:** the boundary held. Where possible this is decided from the host side (a canary that never shows up in the jail's output, a host listener that receives no request, an evidence directory that is byte-for-byte unchanged), not from the probe's own claim.
- **Recorded:** the runner's own report shows the attempt (for example `egressAttempts`, `oomKilled`, `timedOut`). A runner that cannot observe something reports it as unrecorded.

A probe that never started (no start marker in its output) is never counted as contained, so a broken image or runner cannot pass the suite by accident.

| Invariant                 | Probe                                                                                                                                                                       |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| no-egress                 | Resolves a public name, opens TCP connections to a public IPv4 and IPv6 address, and sends a UDP datagram                                                                   |
| no-credential-access      | Dumps its environment and reads the host credential path; the host looks for a canary that the harness put in that file and in the runner's own environment                 |
| no-evidence-store-access  | Reads an exhibit from the host evidence directory and writes a forged one                                                                                                   |
| no-orchestrator-reach     | Sends an HTTP request to a host listener on the Docker bridge gateway, standing in for the orchestrator                                                                     |
| no-writes-outside-scratch | Writes to `/scratch` (control, must succeed) and to `/`, `/etc`, `/tmp`, `/var/tmp`, `/run`, `/dev/shm`, `/dev/mqueue`, `/home/node`, `/root`, `/usr/local/lib`, `/witness` |
| bounded-processes         | Starts up to 1000 sleeping children, then kills them                                                                                                                        |
| bounded-memory            | Allocates and touches memory up to 1536 MiB, above the 1 GiB the Phase 1 runner declares                                                                                    |
| bounded-wall-clock        | Never exits; the runner must stop it within its timeout plus 5 s, measured by the suite's own clock as well as the runner's                                                 |

## How to run

Unit tests for the assessment logic run with the normal `pnpm test` and need no Docker. The suite itself needs a Docker daemon:

```bash
pnpm --filter @affidavit/sandbox containment                   # gVisor runner, writes its table below
pnpm --filter @affidavit/sandbox containment --runner plain     # plain Docker baseline
pnpm --filter @affidavit/sandbox containment --require-pass    # exits 1 unless every probe passes (for L2-11 CI)
```

## Findings

Findings 1 to 6 are from the plain Docker run (2026-11-14, Fedora 44, Docker 29.9.3, runc, SELinux enforcing). Findings 7 and 8 are from the gVisor runner, finding 9 from the witness jail.

1. **bounded-memory is breached by the Phase 1 flags.** `buildDockerRunArgs` sets `--memory 1g` but not `--memory-swap`, so Docker lets the container use as much again in swap. The probe touched 1536 MiB and exited cleanly. Rerunning the same allocation by hand with `--memory-swap 1g` added was OOM-killed (exit 137, `OOMKilled: true`). Fix: set `--memory-swap` equal to `--memory` in `buildDockerRunArgs` (lead-owned, `packages/testing`) and in the L2-02 runner.
2. **Host bind mounts fail under SELinux.** With SELinux enforcing, a file mounted by `buildDockerRunArgs` is unreadable inside the container (`EACCES`), because the mount carries no relabel option. `LocalDockerToolRunner` will therefore fail to read mounted repos on Fedora and RHEL hosts. This is a usability failure, not a containment one, but Lane 1 will hit it in L1-01 and L1-02. Options: `:z` on read-only tool mounts, `:Z` for per-case private mounts, or copying inputs into a volume. The containment runner avoids mounts entirely (probe on stdin, tmpfs `/scratch`).
3. **Almost nothing is recorded on plain Docker.** Only OOM kills and the harness's own timeout are observable. Egress attempts, denied reads and writes, and hitting the pids limit leave no trace in the run report, so six of eight probes fail on "recorded" even where the boundary held. This is the main gap for L2-02 and L2-03 to close. Candidates to evaluate there, not yet tried: gVisor's own syscall and network logs, and the cgroup `pids.events` and `memory.events` counters.
4. **The probes do detect a breach on this host (negative control).** On 2026-11-14 the five isolation probes were run once against a deliberately open runner (default bridge network, writable root, evidence and credential paths mounted, canary env var passed in). All five reported a breach: DNS and TCP egress succeeded, the credential canary leaked, the exhibit was read and a forged one written, and the host listener received a request. So "contained" in the table above reflects the jail, not a firewall or a broken probe. That runner was a one-off script and is not committed.
5. **`/dev/shm` is writable under the Phase 1 flags.** Docker mounts a 64 MiB tmpfs at `/dev/shm` even with `--read-only`. The first version of this suite did not try that path, so it reported writes as contained. The suite now also tries `/var/tmp`, `/run`, `/dev/mqueue` and home directories. The write stays inside the container and is lost at teardown, but it breaks the invariant and gives a witness shared state between processes. Fix in the hardened runner (L2-02).
6. **The Docker socket check in `buildDockerRunArgs` only matches the string `docker.sock`.** A mount of `/var/run` or `/run` (the directory holding the socket), or of `/`, passes the check and would hand the container control of the Docker daemon. `-v` with a path containing `:` can also smuggle extra mount options. Lane 1 passes only its own workspace today, so this is not exploitable yet, but the check should be an allowlist of workspace roots rather than a denylist. The L2-02 runner validates mounts that way. Owner of the fix: lead (`packages/testing`).
7. **Recording, closed on gVisor.** Finding 3 is closed by the L2-02 runner: the `runsc-affidavit` runtime writes a syscall trace that the runner parses into egress attempts, denied reads and writes, and process refusals. gVisor prints the jailed process's command name and path arguments without escaping, which a witness could use to hide a connect; the parser fails closed on any malformed syscall line. Details and the remaining limit in `sandbox-runner.md`.
8. **Under gVisor the pids limit applies on the host, to the sandbox.** Docker's `--pids-limit` counts gVisor's own threads and its host stub processes, not the processes inside the jail. At the limit gVisor cannot create a stub, the jailed `execve` fails with `ENOMEM`, and gVisor logs a warning that the runner records. With `--pids-limit 256` the probe started 113 children before refusal. The bound holds; the number of jailed processes it allows is lower than 256 and depends on gVisor's thread count.
9. **A Docker `--internal` network still reaches the host.** On 2026-11-14 a container under gVisor on a plain `--internal` network fetched from a host listener through the bridge gateway address (172.18.0.1). Every host service that listens on all interfaces, the orchestrator included, would be reachable from a witness. Case networks are now created with `com.docker.network.bridge.inhibit_ipv4=true`, so the host bridge has no address; after that the witness reached none of the host's addresses (LAN, VPN, `docker0`) and still reached the target. `createCaseNetwork` also checks that no host interface sits inside the case subnet. Details in `witness-jail.md`.
